## 1. 프로젝트 개요

### 1-1. 브랜드 아이덴티티

| 항목 | 내용 |
|---|---|
| 브랜드명 | 스테이태그 (Staytag) |
| 카테고리 | 숙박업 성과형 인플루언서 마케팅 중개 |
| 한 줄 정의 | 숙박업체와 인플루언서를 매칭하고, 그 콘텐츠에서 발생한 예약을 추적 코드로 확인해 성과에 따라 정산하는 서비스 |

스테이태그의 고객은 두 종류다 — **수요측**(지방 중소형 숙박업체)과 **공급측**(인플루언서).
**이번 광고의 타겟은 공급측이다.** 양면 시장에서는 공급이 먼저 모여야 수요측에 팔 물건이 생기기 때문이다.

### 1-2. 타겟 페르소나 — "협찬 경험자"

| 구분 | 내용 |
|---|---|
| 상황 | 협찬은 받아봤다. 무료 숙박까지는 얻었다. |
| 결핍 | 거기서 끝났다. 내 게시물이 실제 예약을 만들었는지 확인할 방법이 없었다. |
| 감정 | 내 영향력이 저평가받고 있다는 느낌. 들인 품에 비해 보상이 무료 숙박 한 번으로 정산되는 데 대한 불만. |

### 1-3. USP (인플루언서 관점)

- **가치 약속** — 내 링크로 발생한, 확인된 예약에는 수익이 따라온다.
- **차별점** — 다른 곳은 조회수·게시물 수로 협찬을 끝낸다. 스테이태그는 전화·네이버예약까지 잡는 **코드 회수형 추적**으로 실제 예약을 확인하고, 그 예약에 수익을 배분한다.

> ⚠️ "선불 0원, 실제 예약에만 수수료"는 **숙박업체 관점 USP**다. 이번 광고에는 쓰지 않았다.
> 두 USP를 섞으면 타겟이 모호해진다.

### 1-4. 톤앤매너

| 구분 | 내용 |
|---|---|
| 형식 | **3인칭 에디토리얼 리조트 룩** |
| 시각 | 인물 전신·표정 중심. 크림·테라코타·베이지 파스텔 색조, 풀프레임 35mm 화보 톤 |
| 정서 | 동경을 자극하되 과장하지 않음. **표정과 빛의 변화로** 감정을 옮긴다 |
| 금지 | 사장님 대상 B2B 화법, 빈 객실·매출 장부 등 수요측 이미지 |

> 📌 최초 기획은 '브이로그 1인칭 / 얼굴 정면 최소화'였다. 레퍼런스 이미지를 채택하면서 3인칭으로 전환했고,
> 그 결과 **인물 일관성**이라는 새 과제가 생겨 앵커 3종(§4)을 도입했다.

### 1-5. 캠페인 정의

| 항목 | 내용 |
|---|---|
| 광고 목적 | **인지(Awareness) 집중** |
| 핵심 메시지 | **"무료 숙박에서 끝나지 않아요. 수익도 함께 나눠요."** |
| 영상 길이 | 10.0초 (4씬 · 2.5s / 2.0s / 2.0s / 3.5s) |
| 화면 비율 | 9:16 세로 |
| 브랜드 인지 장치 | 씬 4(6.5~10.0초) 화면 내 `Staytag` 노출 — 편집 자막 없음 |

### 1-6. 서사 구조

| 단계 | 씬 | 역할 | 시간대 |
|---|:--:|---|---|
| 기 | 1 | 익숙한 경험 — "내 얘긴데" 인식 | 낮 |
| 승 | 2 | 콘텐츠를 올렸고 반응도 왔다 | 오후 (골든아워) |
| 전 | 3 | **그런데 성과는 확인되지 않았다** ← 결핍 각인 | 해질녘 (블루아워) |
| 결 | 4 | 확인된 예약엔 수익이 따라온다 + 브랜드 각인 | 다음 날 아침 |

**빛의 시간대가 곧 감정선이다.** 밝음 → 따뜻함 → 파랗게 식음 → 다시 밝음.
네 컷을 이어 붙이면 하루가 흐르므로 서사가 저절로 생긴다.

## 4. 재현 방법 (4단계 요약)

**1단계 — 이미지**
`02_스토리보드.pdf` §3의 씬별 프롬프트를 나노바나나 2에 입력한다.
씬 1을 먼저 확정하고, **씬 1 이미지를 레퍼런스로 첨부**해 씬 2·3·4를 생성한다 → `images/`

> **직전 씬이 아니라 항상 씬 1을 레퍼런스로 쓴다.** 직전 씬을 쓰면 오차가 누적돼
> 씬 4에 가면 인물이 다른 사람이 된다. 기준점을 하나로 고정하는 것이 핵심이다.

**2단계 — 영상**
각 씬 이미지를 Veo 3.1 Lite의 **시작 프레임**으로 넣고 씬별 모션 지시로 생성한다 → `clips/`
씬 4는 **시작·종료 프레임 둘 다 같은 이미지**를 넣는다. 양끝을 고정해야 화면 안 한글이 0~4초 내내 유지된다.

**3단계 — 오디오**
Suno로 BGM(인스트루멘탈), ElevenLabs로 내레이션 4개를 생성한다 → `audio/`

**4단계 — 편집**
아래 §5의 ffmpeg 명령 5단계를 순서대로 실행한다 → `staytag_ad_v1.mp4`

### 앵커 3종 — 모든 이미지 프롬프트에 그대로 붙인다

씬마다 프롬프트를 새로 쓰면 인물과 장소가 조금씩 달라진다. 그래서 **바뀌지 않아야 할 것**을 세 덩어리로 고정하고, 씬별 지시문 뒤에 그대로 이어 붙였다. 전문은 `02_스토리보드.pdf` §2에 있다.

| 앵커 | 고정하는 것 |
|---|---|
| 인물 | 연령대 · 의상 · 헤어 (얼굴이 아니라 **입은 것과 머리 모양**을 고정) |
| 장소 | 리조트 빌라 발코니 · 유리 난간 · 인피니티풀 · 수평선 |

## 5. 편집 실행 순서 (Windows)

> 명령어가 **왜** 그렇게 생겼는지는 §6에 있다. 이 절은 **그대로 따라 하는 순서**만 담는다.

### 5-0. ffmpeg 설치

1. 웹브라우저에서 **https://www.gyan.dev/ffmpeg/builds/** 접속
2. `release builds` 항목에서 **`ffmpeg-release-essentials.zip`** 다운로드
3. 압축을 풀면 `ffmpeg-x.x.x-essentials_build` 폴더가 나온다
4. 그 안의 **`bin` 폴더**에 `ffmpeg.exe`, `ffprobe.exe` 가 있다
5. **`bin` 폴더 안의 파일 3개를 전부** 이 README가 있는 폴더에 복사한다

> **왜 같은 폴더에 넣나**: 환경 변수(PATH) 설정을 안 해도 되기 때문이다.
> 명령어를 실행하는 폴더에 `ffmpeg.exe`가 있으면 바로 인식된다.
> 설치가 아니라 **파일을 옆에 두는 것**이라 나중에 지우기도 쉽다.
> 이 실행 파일들은 용량이 커서 저장소에 포함하지 않았다 (§10).

### 5-1. 명령 프롬프트 열기

1. 탐색기로 이 폴더를 연다
2. 주소창(폴더 경로가 보이는 칸)을 클릭한다
3. 거기에 **`cmd`** 라고 치고 Enter

검은 창이 뜨고 맨 앞에 그 폴더 경로가 보이면 성공이다.

### 5-2. 작업 폴더 만들기

```
mkdir work
```

### 5-3. 1단계 — 트림 + Veo 소리 제거 (4번)

**한 줄씩 복사해서 붙여넣고 Enter.** 네 번 반복한다.

```
ffmpeg -y -i clips\s01_clip_v1.mp4 -t 2.5 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\v1.mp4
```
```
ffmpeg -y -i clips\s02_clip_v1.mp4 -t 2.0 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\v2.mp4
```
```
ffmpeg -y -i clips\s03_clip_v1.mp4 -t 2.0 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\v3.mp4
```
```
ffmpeg -y -i clips\s04_clip_v1.mp4 -t 3.5 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\v4.mp4
```

### 5-4. 2단계 — 순서 목록 만들고 이어붙이기

목록 파일을 만든다. **아래 한 줄을 통째로** 복사해 붙여넣는다.

```
(echo file 'v1.mp4' & echo file 'v2.mp4' & echo file 'v3.mp4' & echo file 'v4.mp4') > work\list.txt
```

이어붙인다.

```
ffmpeg -y -f concat -safe 0 -i work\list.txt -c copy work\video_only.mp4
```

### 5-5. 3단계 — BGM 자르고 볼륨 낮추기

```
ffmpeg -y -ss 2.5 -t 10 -i audio\bgm_v1.mp3 -af "volume=0.18,afade=t=out:st=9:d=1" work\bgm_cut.mp3
```

### 5-6. 4단계 — 내레이션 배치하고 섞기

**가장 긴 명령이다. 한 줄이니 통째로 복사한다.**

```
ffmpeg -y -i work\bgm_cut.mp3 -i audio\s01_vo_v1.mp3 -i audio\s02_vo_v1.mp3 -i audio\s03_vo_v1.mp3 -i audio\s04_vo_v1.mp3 -filter_complex "[1]adelay=0|0[a1];[2]adelay=2500|2500[a2];[3]adelay=4500|4500[a3];[4]adelay=6500|6500[a4];[0][a1][a2][a3][a4]amix=inputs=5:duration=first:normalize=0[out]" -map "[out]" work\audio_mix.m4a
```

### 5-7. 5단계 — 영상과 소리 합치기

```
ffmpeg -y -i work\video_only.mp4 -i work\audio_mix.m4a -c:v copy -c:a aac -b:a 192k -shortest staytag_ad_v1.mp4
```

### 5-8. 검증

```
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate -of default=noprint_wrappers=1 staytag_ad_v1.mp4
```

나와야 하는 값:

```
codec_name=h264
codec_type=video
width=720
height=1280
r_frame_rate=24/1
codec_name=aac
codec_type=audio
duration=10.000000
```

**`duration=10.000000`** 과 **`aac`** 두 개만 확인하면 미션 요건은 충족이다.

### 5-9. 문제가 생기면

| 증상 | 원인 | 해결 |
|---|---|---|
| `'ffmpeg'은(는) 내부 또는 외부 명령... 아닙니다` | `ffmpeg.exe`가 그 폴더에 없다 | 5-0의 5번을 다시 확인 |
| `No such file or directory` | 파일 이름이 다르다 | `dir clips` 로 실제 파일명 확인 |
| 소리가 안 들린다 | 4단계를 건너뛰었다 | `work\audio_mix.m4a` 가 있는지 확인 |
| 목소리가 음악에 묻힌다 | 볼륨 값 문제 | 3단계에서 `volume=0.18` → `0.12` 로 낮춰 다시 |
| 마지막이 뚝 끊긴다 | 페이드아웃 누락 | 3단계 명령에 `afade` 부분이 들어갔는지 확인 |

> `work` 폴더의 중간 파일은 **작업 중에는 지우지 않는다.** 어느 단계에서 무엇이 나왔는지 보여주는
> 기록이고, 문제가 생겼을 때 그 단계만 다시 할 수 있다. 저장소에는 올리지 않는다 (§10).

### 5-10. 16:9 버전 편집 — **5단계가 아니라 3단계**

보너스 E3(§9-E)로 만든 16:9 버전은 위 절차에서 **3단계와 4단계를 통째로 건너뛴다.**

| 단계 | 9:16 | 16:9 |
|:--:|---|---|
| 1 | 트림 + 음소거 ×4 | 필요 (경로만 다름) |
| 2 | 이어붙이기 | 필요 |
| 3 | BGM 자르기 | **생략 — `work\bgm_cut.mp3` 재사용** |
| 4 | 내레이션 배치·믹스 | **생략 — `work\audio_mix.m4a` 재사용** |
| 5 | 영상 + 소리 합치기 | 필요 |

씬 길이가 2.5 / 2.0 / 2.0 / 3.5초로 같기 때문에 **오디오는 한 글자도 바뀔 게 없다.**
소리를 영상과 분리해 따로 만들어 둔 설계가 여기서 값을 한다.
편집 프로그램 타임라인에 전부 얹어놨다면 두 번째 비율을 만들 때 처음부터 다시 깔아야 했다.

```
ffmpeg -y -i clips\16x9\s01_clip_16x9_v1.mp4 -t 2.5 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\w1.mp4
```
```
ffmpeg -y -i clips\16x9\s02_clip_16x9_v1.mp4 -t 2.0 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\w2.mp4
```
```
ffmpeg -y -i clips\16x9\s03_clip_16x9_v1.mp4 -t 2.0 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\w3.mp4
```
```
ffmpeg -y -i clips\16x9\s04_clip_16x9_v1.mp4 -t 3.5 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work\w4.mp4
```
```
(echo file 'w1.mp4' & echo file 'w2.mp4' & echo file 'w3.mp4' & echo file 'w4.mp4') > work\list_16x9.txt
```
```
ffmpeg -y -f concat -safe 0 -i work\list_16x9.txt -c copy work\video_only_16x9.mp4
```
```
ffmpeg -y -i work\video_only_16x9.mp4 -i work\audio_mix.m4a -c:v copy -c:a aac -b:a 192k -shortest staytag_ad_16x9_v1.mp4
```

> **중간 파일 이름을 `v1~v4`가 아니라 `w1~w4`로 쓴 이유**: 같은 `work\` 폴더에 9:16 중간 파일이
> 남아 있어서, 같은 이름을 쓰면 덮어쓴다. 9:16을 다시 손봐야 할 때 근거가 사라진다.

## 6. 편집 명령어 · 라인별 해설

> "무엇을 하는지"가 아니라 **"왜 이렇게 동작하는지"** 를 쓴다.

### 6-0. ffmpeg란 무엇인가

**영상·소리 파일을 다루는 명령어 도구**다. 버튼이 있는 프로그램이 아니라 **글자로 명령을 적어 실행**한다.

편집 프로그램(CapCut 등)이 화면에서 클립을 끌어다 놓는 방식이라면, ffmpeg는 **"이 파일의 앞 2.5초만 잘라서 저 파일로 저장해"** 라고 문장으로 지시한다.

**왜 이걸 골랐나**: 컷 타이밍이 소수점까지 정확해야 했다. 우리 씬은 2.5 / 2.0 / 2.0 / 3.5초로 정해져 있고, 내레이션도 0.01초 단위로 재서 맞췄다. 마우스로 끌어 맞추면 이 정밀도가 나오지 않는다.

### 6-1. 왜 명령어를 5개로 나눴나

한 줄로 다 할 수도 있었다. 그러면 이렇게 된다.

```
ffmpeg -i a.mp4 -i b.mp4 -i c.mp4 -i d.mp4 -i bgm.mp3 -i v1.mp3 ... -filter_complex "[0:v][1:v][2:v][3:v]concat=n=4:v=1[v];[5]adelay=...[a1];...[mix]" -map "[v]" -map "[mix]" out.mp4
```

**읽을 수 없다.** 그리고 중간에 뭐가 잘못되면 **어디서 틀렸는지 알 수 없다.**

5개로 나누면 단계마다 결과 파일이 남는다. 3단계 결과가 이상하면 3단계만 다시 하면 된다. **각 명령이 한 가지 일만 하므로 한 줄씩 설명할 수 있다.**

> 이건 이 미션의 다른 결정들과 같은 원리다. 스토리보드에서 씬 정보와 프롬프트를 한 블록으로 합친 것도,
> 프롬프트를 앵커로 쪼갠 것도 **"고칠 때 어디를 봐야 하는지 명확하게"** 만들기 위한 것이었다.

### 6-2. 1단계 — 트림 + Veo 오디오 제거

```
ffmpeg -y -i clips/s01_clip_v1.mp4 -t 2.5 -an -c:v libx264 -crf 18 -pix_fmt yuv420p work/v1.mp4
```

| 부분 | 뜻 | 왜 필요한가 |
|---|---|---|
| `-y` | 같은 이름 파일이 있으면 덮어쓴다 | 없으면 "덮어쓸까요?" 하고 멈춰서 다시 눌러야 한다 |
| `-i clips/s01_clip_v1.mp4` | 입력 파일 | `-i`는 input |
| `-t 2.5` | **앞에서 2.5초만** 쓴다 | 클립은 8초로 생성됐다. 씬 1은 2.5초만 필요하다 |
| **`-an`** | **소리를 버린다** | **여기가 핵심이다.** 아래 참조 |
| `-c:v libx264` | 영상을 H.264로 다시 인코딩 | 미션이 요구하는 코덱 |
| `-crf 18` | 화질 (숫자가 작을수록 고화질) | 18은 눈으로 원본과 구분이 어려운 수준 |
| `-pix_fmt yuv420p` | 색상 저장 방식 | 이게 없으면 일부 플레이어에서 재생이 안 된다 |

#### `-an` 이 왜 핵심인가

Veo는 클립마다 **자기가 만든 소리를 붙여서** 내보낸다. 그런데 그 소리는 **클립별로 따로 만들어진 것**이라, 4개를 이어 붙이면 **소리가 4번 뚝뚝 끊긴다.**

우리는 통일된 BGM 하나를 10초 내내 깔 계획이므로, **Veo 소리를 먼저 완전히 버려야** 한다. `-an`은 audio none, 즉 "소리 없이"라는 뜻이다.

> **미션 규정과의 관계**: 미션은 편집 도구를 "컷 편집·자막·간단 색보정·**오디오 레벨 조정**"으로 제한한다.
> 소리를 끄는 것은 레벨 조정의 극단(0으로 내림)이므로 허용 범위 안이다.

이 명령을 **씬 4개에 대해 4번** 실행한다. `-t` 값만 각각 2.5 / 2.0 / 2.0 / 3.5로 바뀐다.

### 6-3. 2단계 — 영상 이어붙이기

먼저 **순서를 적은 목록 파일**을 만든다.

```
file 'v1.mp4'
file 'v2.mp4'
file 'v3.mp4'
file 'v4.mp4'
```

그다음 이어붙인다.

```
ffmpeg -y -f concat -safe 0 -i work/list.txt -c copy work/video_only.mp4
```

| 부분 | 뜻 |
|---|---|
| `-f concat` | 입력을 "이어붙일 목록"으로 읽으라는 뜻 |
| `-safe 0` | 파일 경로 검사를 완화 (한글 폴더명 때문에 필요) |
| **`-c copy`** | **다시 인코딩하지 않고 그대로 복사** |

#### `-c copy` 가 왜 중요한가

1단계에서 이미 H.264로 인코딩했다. 여기서 또 인코딩하면 **화질이 한 번 더 손실된다.** JPG를 열었다 저장할 때마다 조금씩 나빠지는 것과 같다.

`-c copy`는 **영상 데이터를 건드리지 않고 이어붙이기만** 한다. 그래서 빠르고 화질 손실이 없다.

이게 가능한 이유는 **네 파일이 같은 형식**이기 때문이다. 해상도·프레임레이트·코덱이 다르면 `-c copy`로는 못 붙인다. 1단계에서 넷을 똑같은 조건으로 인코딩해 둔 것이 여기서 값을 한다.

### 6-4. 3단계 — BGM 자르고 볼륨 낮추기

```
ffmpeg -y -ss 2.5 -t 10 -i audio/bgm_v1.mp3 -af "volume=0.18,afade=t=out:st=9:d=1" work/bgm_cut.mp3
```

| 부분 | 뜻 |
|---|---|
| `-ss 2.5` | 2.5초 지점부터 시작 |
| `-t 10` | 거기서 10초 분량 |
| `-af` | audio filter — 소리에 가공을 건다 |
| `volume=0.18` | 음량을 0.18배로 |
| `afade=t=out:st=9:d=1` | 9초 지점부터 1초 동안 서서히 사라짐 |

#### `-ss 2.5` — 왜 2.5초부터인가

Suno가 만든 곡은 **3분 55초**다. 10초를 잘라야 하는데, **어디를 자르느냐를 측정으로 정했다.**

| 구간 | 평균 음량 | 판정 |
|---|---|---|
| 0 ~ 2.4초 | 거의 무음 | 곡 시작 전 공백 |
| **2.5 ~ 12.5초** | **-17.0 dB** | **채택** |
| 27초 이후 | -13.7 dB | 악기가 쌓여 목소리를 덮는다 |

곡은 뒤로 갈수록 악기가 쌓인다. **인트로가 가장 조용하고, 그게 우리에겐 장점**이다. 이 영상의 주인공은 목소리이고 음악은 바닥이기 때문이다.

앞 2.4초는 소리가 없어서 제외했다. 2.5초부터는 0.3초 이상 끊기는 곳도 없다.

#### `volume=0.18` — 이 숫자는 어떻게 나왔나

**귀로 맞춘 게 아니라 재서 계산했다.**

```
BGM   평균 -17.0 dB
목소리 평균 -22   dB   ← BGM보다 5dB 작다
```

**이대로 섞으면 음악이 목소리를 덮는다.** 광고에서는 목소리가 음악보다 **10dB 이상 위**에 있어야 또렷하게 들린다.

BGM을 15dB 낮추면 -32dB가 되어 목소리보다 10dB 아래로 내려간다. 음량을 15dB 낮추는 배율은

```
0.18배  ≒  10의 (-15 ÷ 20) 제곱
```

**dB는 배율을 로그로 표현한 단위**라 이런 계산이 나온다. 대략 이렇게 기억하면 된다.

| 낮추는 양 | 배율 |
|---|---|
| 6 dB | 0.5배 (절반) |
| 12 dB | 0.25배 |
| 20 dB | 0.1배 |

실제 결과는 BGM -32.8 dB로 계산과 맞았다.

#### `afade` — 왜 끝을 흐리게 하나

음악이 10초에 **뚝 끊기면 듣는 사람이 놀란다.** 마지막 1초를 서서히 줄이면 자연스럽게 닫힌다.

`t=out`은 fade out, `st=9`는 시작 시각 9초, `d=1`은 1초 동안이라는 뜻이다.

### 6-5. 4단계 — 내레이션 배치하고 섞기

```
ffmpeg -y -i work/bgm_cut.mp3 -i audio/s01_vo_v1.mp3 -i audio/s02_vo_v1.mp3 -i audio/s03_vo_v1.mp3 -i audio/s04_vo_v1.mp3 -filter_complex "[1]adelay=0|0[a1];[2]adelay=2500|2500[a2];[3]adelay=4500|4500[a3];[4]adelay=6500|6500[a4];[0][a1][a2][a3][a4]amix=inputs=5:duration=first:normalize=0[out]" -map "[out]" work/audio_mix.m4a
```

**이 미션에서 가장 복잡한 한 줄**이다. 나눠서 본다.

#### 입력에 번호가 붙는다

```
-i bgm_cut.mp3      → [0]
-i s01_vo_v1.mp3    → [1]
-i s02_vo_v1.mp3    → [2]
-i s03_vo_v1.mp3    → [3]
-i s04_vo_v1.mp3    → [4]
```

`-i`로 넣은 순서대로 **0번부터 번호가 매겨진다.** 뒤의 필터에서 이 번호로 각 파일을 가리킨다.

#### `adelay` — 소리를 뒤로 미룬다

```
[2]adelay=2500|2500[a2]
```

**"2번 파일(씬 2 내레이션)을 2500밀리초 = 2.5초 뒤로 미뤄서 a2라고 부르겠다"**

씬 2가 2.5초에 시작하므로 그 목소리도 2.5초에 나와야 한다. 앞에 2.5초짜리 무음을 붙이는 셈이다.

| 파일 | 미루는 시간 | 이유 |
|---|---|---|
| 씬 1 | 0 | 영상 시작과 동시 |
| 씬 2 | 2500 (2.5초) | 씬 2 시작 시각 |
| 씬 3 | 4500 (4.5초) | 씬 3 시작 시각 |
| 씬 4 | 6500 (6.5초) | 씬 4 시작 시각 |

**`2500|2500` 처럼 두 번 쓰는 이유**: 스테레오라 왼쪽·오른쪽 채널이 따로 있다. 둘 다 똑같이 미뤄야 소리가 한쪽으로 치우치지 않는다. `|`는 채널 구분 기호다.

#### `amix` — 다섯 개를 하나로 겹친다

```
[0][a1][a2][a3][a4]amix=inputs=5:duration=first:normalize=0[out]
```

BGM 1개 + 내레이션 4개 = **5개를 동시에 재생되도록 겹친다.**

| 옵션 | 뜻 | 왜 필요한가 |
|---|---|---|
| `inputs=5` | 5개를 섞는다 | |
| `duration=first` | 길이는 **첫 번째 입력(BGM)** 기준 | 이게 없으면 가장 긴 파일에 맞춰져 10초를 넘는다 |
| **`normalize=0`** | **자동 음량 조정을 끈다** | **여기가 함정이다.** 아래 참조 |

#### `normalize=0` — 이걸 빠뜨리면 소리가 작아진다

`amix`는 기본값으로 **입력 개수만큼 음량을 나눈다.** 5개를 섞으면 각각이 **1/5로 줄어든다.**

여러 소리를 겹칠 때 음량이 넘쳐 깨지는 걸 막으려는 안전장치인데, **우리는 이미 BGM 음량을 계산해서 맞춰뒀다.** 여기서 또 나누면 애써 맞춘 비율이 무너지고 전체가 작아진다.

`normalize=0`은 **"내가 계산해뒀으니 건드리지 마"** 라는 뜻이다.

> 대신 음량이 넘칠 위험은 직접 확인해야 한다.
> 완성본의 최대 음량을 재보니 **-5.8 dB**로 0dB 아래라 깨지지 않았다.

#### `-map "[out]"` — 결과 지정

필터를 거친 결과 `[out]`을 최종 출력으로 쓰겠다는 뜻이다. 이게 없으면 ffmpeg가 원본 중 하나를 그냥 내보낸다.

### 6-6. 5단계 — 영상과 소리 합치기

```
ffmpeg -y -i work/video_only.mp4 -i work/audio_mix.m4a -c:v copy -c:a aac -b:a 192k -shortest staytag_ad_v1.mp4
```

| 부분 | 뜻 | 왜 |
|---|---|---|
| `-c:v copy` | 영상은 그대로 복사 | 이미 완성된 영상이라 다시 인코딩할 이유가 없다 |
| `-c:a aac` | 소리는 AAC로 인코딩 | **미션이 요구하는 오디오 코덱** |
| `-b:a 192k` | 소리 품질 | 192kbps면 광고용으로 충분하다 |
| `-shortest` | 둘 중 짧은 쪽에 맞춰 끝낸다 | 영상 10.000초, 소리 10.032초 → **10.000초에 맞춰 자른다** |

`-shortest`가 없으면 마지막 0.032초 동안 **소리만 나오고 화면이 멈춘다.**

### 6-7. 이 편집에서 지킨 원칙 세 가지

**① 한 명령은 한 가지 일만 한다**
5개로 나눠 단계마다 결과가 남게 했다. 문제가 생기면 그 단계만 다시 한다.

**② 다시 인코딩하지 않을 수 있으면 하지 않는다**
`-c copy`를 쓸 수 있는 곳에서는 썼다. 인코딩할 때마다 화질이 손실되기 때문이다.

**③ 숫자는 재서 정한다**
`volume=0.18`도, BGM 시작점 2.5초도, 컷 타이밍도 전부 측정 결과에서 나왔다.
귀로 "이쯤"이 아니라 dB와 초 단위로 계산했다.

### 6-8. 편집에서 실제로 한 작업 (제약 준수 근거)

미션은 편집 도구를 "컷 편집·자막·간단 색보정·오디오 레벨 조정 등 통합 편집 용도로만 제한적으로" 쓰라고 요구한다. ffmpeg로 수행한 작업은 **아래 4가지가 전부**다.

| 작업 | 명령 | 미션 허용 범위 |
|---|---|---|
| 트림 (앞부분만 사용) | `-t 2.5` 등 | 컷 편집 |
| Veo 네이티브 오디오 제거 | `-an` | 오디오 레벨 조정 (0으로) |
| 네 클립 이어붙이기 | `-f concat -c copy` | 컷 편집 |
| BGM 음량·페이드, 내레이션 배치·믹스 | `volume` `afade` `adelay` `amix` | 오디오 레벨 조정 |

**하지 않은 것**: 화면 합성, 전환 효과, 색보정, 자막 삽입, 속도 변경, 크롭.

> 연출을 편집이 아니라 **생성 단계로 앞당긴** 결과다.
> 씬 3·4의 명암 대비를 전환 효과가 아니라 프롬프트의 시간대 지정으로 만들었기 때문에
> 편집에서 할 일이 거의 남지 않았다. 제약을 피한 게 아니라 **제약에 맞춰 설계 위치를 옮겼다.**

### 왜 해시를 기록하나

제작 중 **파일명과 실제 내용이 어긋난 사고가 네 번** 있었다.
확장자 중복 1회, 씬 번호 혼동 2회, 클립 중복 저장 1회.

생성 도구의 다운로드 목록에서 결과물이 서로 비슷해 보여 눈으로 구분하기 어려웠던 것이 원인이다.
md5는 파일 내용을 요약한 지문이라 **이름이 달라도 내용이 같으면 같은 값**이 나온다.
사람이 목록을 훑는 것보다 확실하다.

재검증 명령:

```bash
md5sum images/* clips/* audio/* staytag_ad_v1.mp4
md5sum images/16x9/* clips/16x9/* staytag_ad_16x9_v1.mp4
```

### 파일명 규칙

```
s{씬번호 2자리}_{종류}_{버전}.{확장자}
```

| 요소 | 값 |
|---|---|
| 씬번호 | `01` ~ `04` (2자리 고정 — 파일 정렬이 씬 순서와 일치) |
| 종류 | `img` 이미지 / `clip` 영상 클립 / `vo` 내레이션 |
| 버전 | `v1` `v2` … 수정할 때마다 증가 |
| 확장자 | 도구가 내보내는 그대로 (이미지는 `.png`, 씬 4 v1만 `.jpeg`) |

씬에 묶이지 않는 파일은 씬번호를 뺀다: `bgm_v1.mp3`, `staytag_ad_v1.mp4`

> ⚠️ **`s01_img_v2`는 씬 1의 2번째 시도**이지 씬 2가 아니다.
> 앞자리는 씬 번호, 뒷자리는 그 씬의 몇 번째 시도다. 실제로 두 번 틀렸던 지점이다.

**16:9 버전**은 `images/16x9/` `clips/16x9/` 하위 폴더로 분리하고, 파일명에도 비율을 넣었다.

```
s{씬번호}_{종류}_16x9_{버전}.{확장자}      예: s01_img_16x9_v3.png
```

폴더만 나눠도 구분은 되지만, **파일을 하나만 떼어 봤을 때도 어느 버전인지 알 수 있어야** 하기 때문이다.
이 프로젝트에서 파일명·내용 불일치 사고가 네 번 났던 것을 감안한 이중 표시다.

## 9-E. 보너스 E3 상세 — 16:9 버전

### 왜 크롭이 아니라 재생성인가

기존 9:16 영상을 ffmpeg로 잘라 16:9를 만들 수도 있었다. 그렇게 하지 않은 이유는 둘이다.

| 이유 | 설명 |
|---|---|
| **제약 위반** | §6-8에 "하지 않은 것: 크롭"이라고 명시했다. 크롭하면 D6 방어 논리가 무너진다 |
| **품질** | 720×1280을 16:9로 자르려면 위아래를 크게 버려야 해서 **인물 전신이 남지 않는다** |

재생성은 이미지 4 + 영상 4 = 크레딧 8회분이 들었지만, **앵커 3종이 이미 있어서 인물·장소는 그대로 유지**됐다.
앵커를 텍스트로 고정해 둔 설계가 두 번째 비율을 만들 때 회수된 셈이다.

### 세로 → 가로에서 실제로 바꾼 것

앵커 3종은 **한 글자도 바꾸지 않았다.** 바뀐 건 구도 지시뿐이다.

| 바꾼 것 | 세로에서는 | 가로에서 필요한 이유 |
|---|---|---|
| `오른쪽` → `오른쪽 3분의 1 지점` | 좌우가 좁아 "오른쪽"으로 충분 | 좌우가 넓어져 **어디가 오른쪽인지 폭이 생긴다** |
| `익스트림 와이드 샷` 추가 | 전신이 저절로 들어옴 | **위아래가 좁아 다리·모자가 잘린다** |
| `수평선은 화면 위쪽 3분의 1 높이` 추가 | 문제되지 않음 | 가로 사진은 수평선 높이가 안정감을 좌우 |
| 씬 4 카드에 `세로로 긴 직사각형` `화면 높이의 3분의 2` | 여백이 좁아 저절로 맞음 | 왼쪽 여백이 넓어져 **카드가 가로로 퍼진다** |

**세로는 위아래로 정보를 쌓고, 가로는 좌우로 나눈다.** 같은 스토리보드라도 이 차이만큼은 조정해야 했다.

### 씬 1의 수정 이력 (v1 → v2 → v3)

| 버전 | 문제 | 조치 |
|:--:|---|---|
| v1 | **인물이 카메라를 응시** — 3인칭 에디토리얼 톤과 어긋남 | `왼쪽의 바다와 수영장 풍경을 바라보고 있어` + `카메라를 보지 않고 옆얼굴이 보이는 각도야` 로 교체 |
| v2 | 시선은 고쳐졌으나 **발이 프레임 밖으로 잘림** | `발끝부터 모자 끝까지 프레임 안에` → `카메라가 인물에게서 멀리 떨어진 익스트림 와이드 샷이야` 로 교체 |
| **v3** | 없음 — **채택** | |

**v2에서 배운 것**: `프레임 안에 다 들어와` 는 *결과 상태*를 말한 것이라 도구가 카메라 위치를 스스로 정해야 한다.
`익스트림 와이드 샷` 은 *카메라와 피사체의 거리*를 지정하는 촬영 용어라 해석 폭이 좁다.
씬 3(9:16)에서 `작게` 가 실패하고 같은 용어가 성공했던 것과 **완전히 같은 패턴**이다 (§6 원리).

### Veo 모션 지시 (16:9)

설정은 9:16과 같고 **화면 비율만 16:9로 바꾼다.** Veo 3.1 Lite · 8초 생성 · 앞 구간 사용.

| 2 | 카메라 고정. 엄지로 폰 화면을 한 번 위로 넘기고 미소가 번진다. 역광이 미세하게 흔들린다. **폰 화면은 계속 흐릿하게 유지.** 말하지 않는다 |
| 3 | 카메라가 아주 느리게 **뒤로 물러난다.** 뒷모습 그대로 거의 정지. 치마·머리카락만 흔들림. **폰 화면은 끝까지 꺼진 상태.** 파란 빛이 밝아지지 않는다 |
| 4 | 카메라 완전 고정. 놀란 표정에서 환한 미소로 조금 변한다. **왼쪽 카드는 위치·크기·글자가 처음부터 끝까지 전혀 변하지 않는다.** 한 글자도 바뀌거나 사라지지 않는다. 새 글자·자막 추가 없음 |

**씬 4만 시작 프레임과 종료 프레임에 같은 이미지를 넣는다.** 양끝이 고정되면 AI가 중간을 그 사이로만
채우므로 한글이 유지된다. 완벽하지는 않고(9:16에서 "증" 한 글자 손실) **손실을 줄이는 방법**이다.

> ⚠️ **9:16 클립을 만들 때 쓴 모션 지시는 문서로 남기지 않았다.** 대화로만 주고받고 옮겨 적지 않은 결과다.
> 기억에 의존해 복원하면 실제로 입력한 문장과 달라질 수 있어 **적지 않는 쪽을 택했다.**

## 12. 이 미션에서 배운 것

### ① 작업 도구를 바꾸니 진행 방식이 바뀌었다

이전 미션은 코디세이 자체 AI인 **네이토**로 진행했다. 이번에는 개인 **클로드 코워크**를 썼는데,
**한 번에 한 단계씩 끊어서 확인하며 진행하는 방식**이 훨씬 수월했다.

결과물을 통째로 받는 대신 단위별로 끊었기 때문에, 잘못된 부분을 **그 단계에서** 발견할 수 있었다.
제작 중 파일명과 실제 내용이 어긋난 사고가 네 번 있었는데(§8), 전부 다음 단계로 넘어가기 전에 잡혔다.
마지막에 한꺼번에 확인했다면 어디서부터 틀렸는지 되짚기 어려웠을 것이다.

### ② 미뤄두던 도구를 실제로 써봤다

**Suno**와 **ElevenLabs**는 "한번 써봐야지" 하고 미뤄두기만 했던 도구였다.
이번 미션이 계기가 되어 처음 사용했고, BGM 1곡과 한국어 내레이션 4개를 직접 만들었다.

써보고 나서야 알게 된 것들이 있다. Suno가 만든 곡은 **뒤로 갈수록 악기가 쌓여** 인트로가 가장 조용했고,
그래서 광고 배경음으로는 앞부분이 유리했다(§6-4). ElevenLabs는 **Style 값을 올리면 억양이 과장돼서**
0~0.2로 낮게 두는 편이 내레이션에 맞았다(§3). 읽어서 아는 것과 직접 돌려보고 아는 것이 달랐다.

### ③ 터미널에서 명령어로 영상을 다뤘다

**ffmpeg** 라는 오픈소스 도구로 영상 편집 전 과정을 명령어로 실행했다.

| 한 일 | 쓴 명령 |
|---|---|
| 자르기 | `-t 2.5` |
| 이어 붙이기 | `-f concat -c copy` |
| 인코딩 | `-c:v libx264` · `-c:a aac` |
| 음량 조정 | `volume=0.18` · `afade` · `amix` |

버튼을 누르는 편집 프로그램이 아니라 **글자로 지시하는 방식**이라 처음에는 낯설었다.
대신 **컷 타이밍을 소수점까지 정확히 지정할 수 있다**는 장점이 있었고,
음량도 귀로 맞추는 대신 dB를 재서 계산으로 정할 수 있었다(§6-4).

명령을 5개로 나눠 단계마다 결과 파일이 남게 한 덕분에,
문제가 생겼을 때 처음부터 다시 하지 않고 **그 단계만 다시 실행**하면 됐다.
